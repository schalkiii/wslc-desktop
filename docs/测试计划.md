# wslc-desktop 测试计划

> 目标：feature 矩阵全覆盖的可回归测试体系。自动化单测覆盖全部**逻辑层**（wslc 后端 + UI 状态逻辑）；纯渲染与真实进程交互列入手动冒烟清单。
> 运行方式：`cargo test`（45 例）；lint 门禁：`cargo clippy --all-targets`（零警告）+ `cargo fmt --check`。

## 1. 覆盖策略

| 层 | 测试方式 | 说明 |
|---|---|---|
| `wslc/client.rs`（进程执行、JSON 解析） | 单测（纯函数）+ 手动冒烟 | 超时/kill、进程 spawn 依赖真实 wslc，无法自动化 |
| `wslc/types.rs`（serde 双 schema 模型） | 单测（2.x/3.x 真实样例回归） | 样例取自本机 wslc 2.9.3.0 / 3.0.1.0 实测输出 |
| `wslc/commands.rs`（命令封装、RunSpec、tokenize） | 单测 | `to_args`/`preview` 全参数矩阵 |
| `poller.rs`（后台线程） | 手动冒烟 | mpsc 线程编排依赖 egui Context，自动化成本高 |
| `app.rs`（状态、RunDialog、预设库） | 单测 + 手动冒烟 | 可纯函数化的逻辑全部下沉测试 |
| `ui/layout.rs`（表格、过滤、截断） | 单测（自由函数）+ 手动 | egui 渲染本身不可单测 |
| `ui/dialogs.rs`（镜像源重写） | 单测 | rewrite_registry 全边界 |
| 端到端（真实 wslc 调用） | 手动冒烟清单 | 见 §4 |

## 3. 审查修复记录（本计划伴随的 bugfix）

| 问题 | 修复 |
|---|---|
| 预设库硬编码真实密码与内网 IP，已随仓库公开 | 占位化（`<your-password>` / `<proxy-host>`）+ 回归护栏测试 #37；真实凭据外置到 gitignore 的 `presets.local.json`（按 name 覆盖内置）；git 历史用 `git filter-repo --replace-text` 全量清洗并强推 |
| Run 向导 command 按空格硬拆，`bash -c "…"` 引号 payload 被撕碎 | 复用 shell 式 tokenize（与保存命令路径一致） |
| preview 对含空格参数不加引号，复制后不可执行 | preview 按需加引号 |
| poller 快照"一票否决"：卷解析失败会清空容器/镜像视图 | 卷/网络改为尽力而为，仅容器/镜像硬错误 |
| `RunDialog::list` 注释称支持空格分隔，实现只支持逗号 | 修注释并说明理由（保护含空格路径） |

## 4. 手动冒烟清单（发布前执行）

1. `wslc version` 显示于标题/顶栏；快照 2s 自动刷新，状态栏计数正确。
2. 容器表：Exited 容器可见；排序（Name/State/CPU… 点击表头）与过滤（大小写混输）生效；状态徽章颜色正确。
3. 对运行中容器：CPU/Mem/Net/Block/PIDs 列实时变化；选中后 Stats 图表滚动。
4. Logs：one-shot 与 follow 流切换；时间戳开关；copy-all。
5. Inspect：容器/镜像/卷/网络各 section 均出 JSON；Exec 对运行容器可用。
6. 生命周期：start/stop/restart/kill/remove/prune 各执行一次并核对 toast 与列表刷新。
7. Run 向导：填全参数核对 preview 行；运行一个 `--rm` 短命镜像验证参数真实传递。
8. Pull 对话框：一键镜像源逐个点击核对重写结果；pull 后镜像表刷新且 In-Use 列正确。
9. 卷/网络：创建、删除、prune。
10. 保存命令：新增/编辑/删除/排序/一键运行；"恢复预设"只补缺失项。
11. 主题切换、UI 缩放（80%-250%）拖动并重启验证持久化。

## 5. 已知限制

- `strip_copyright_header` 对首行恰为 banner 样式的日志行存在理论误杀（实测 wslc 3.x 的 version/logs/list 均无版权头，风险极低，保留防御逻辑）。
- `tokenize` 不支持同类引号嵌套转义（`"a \"b\" c"`），与保存命令提示一致。
- `wslc run` 错误回显完整命令行（含 `-e KEY=VALUE` 值）：本地单用户工具不脱敏，避免破坏调试信息。
- 依赖真实 wslc 引擎的端到端行为（首次拉取、超时 kill、VM 冷启动）无法在 CI 稳定复现，依赖手动冒烟。
