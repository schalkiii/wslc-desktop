# wslc-desktop — 竞品拆解与架构/技术方案

> 用 GUI 管理 Microsoft WSL Containers (`wslc.exe`) 的桌面工具
>
> 文档版本：v0.1 · 起草时间：2026-07-15 21:45 (GMT+8) · 状态：方案评审稿

---

## 1. 背景与定位

Microsoft 在 Build 2026 发布 **WSL Containers**（`wslc.exe`），2026-06-29 进入公开预览。它把 OCI 容器能力原生内建进 WSL，命令语法与 Docker 高度一致，但官方明确 **CLI-first、无官方 GUI**。

调研（见 `.workbuddy/memory/2026-07-15.md`）确认：目前**没有任何 Docker-Desktop 级的窗口化 GUI 专门适配 wslc**，仅有两个终端 TUI（`lazywslc`、`lazywslcontainer`）。这正是本项目的机会点。

**产品一句话**：`wslc-desktop` = 一个纯 Rust、单文件、零运行时依赖的桌面 GUI，把 `wslc` 的容器 / 镜像 / 卷 / 网络 / 日志 / 实时统计一屏可视化管理。

> **文档状态**：v0.5 · 2026-07-15 23:55 更新——新增应用图标、将 Stats 列（CPU / Mem / Mem% / Net I/O / Block I/O / PIDs）直接嵌入容器列表；清理冗余 Stats 总览网格。此前 v0.4：新增「常用命令库（Saved Commands）」能力。

## 2. 竞品拆解

### 2.1 三个竞品概览

| 维度 | lazywslc | lazywslcontainer | Docker Desktop |
|---|---|---|---|
| 作者 | Craig Loewen (MSFT, WSL 负责人) | Gregor Pilar (第三方) | Docker, Inc. |
| 许可 | MIT | MIT | 商业（大团队付费） |
| 形态 | 终端 **TUI** | 终端 **TUI** | 窗口化 **GUI** |
| 语言/栈 | **Rust** · ratatui 0.29 + crossterm + tokio | **Go** · bubbletea + lipgloss | Electron+React 前端 / Go 后端 |
| 后端 | 直接调用 `wslc.exe` | 直接调用 `wslc.exe` | 自带 dockerd→containerd→runc（共享 Linux VM） |
| 适配 wslc | ✅ 原生 | ✅ 原生 | ❌（自带运行时，非 wslc） |
| 统计可视化 | ratatui 图表 | 3 行 ASCII sparkline，60 样本 2s | 完整图形面板 |
| 生态 | 无 | 无 | Compose / K8s / 扩展 / Scout / Model Runner |

**核心结论**：两个 wslc 专用工具**都是 TUI**，无一是窗口化 GUI。Docker Desktop 是 GUI 但**不接 wslc**。→ wslc 的 GUI 空白确认成立。

### 2.2 lazywslc（Rust，主要参考对象）

架构分层清晰，是本项目**后端可直接借鉴的范式**：

- **`src/wslc/client.rs`** — 进程派生层：
  - `const WSLC = "wslc.exe"`；`run_bounded()` 用 tokio 派生进程，`Stdio::piped()`。
  - **Windows 关键**：`CREATE_NO_WINDOW`（0x08000000）标志，避免每次调用弹出黑窗。
  - 防御：1 MB 输出上限、10s 超时（超时 kill）、stdout 空 + stderr 非空 → 判错。
  - `strip_copyright_header()` 去掉可能的版权/隐私提示前导行。
- **`src/wslc/commands.rs`** — 命令封装：list/images/volume/stats 全部 `--format json`；start/stop/kill/remove/rmi/pull/run/prune 等。
- **`src/wslc/types.rs`** — serde 结构，`#[serde(rename_all = "PascalCase")]`，附 `state_label()/is_running()/short_id()/human_size()/relative_time()` 等辅助方法。
- **`src/app.rs`** — App 状态 + 轮询 + `StatsHistory { cpu: VecDeque<f64>, memory: VecDeque<f64> }`（`MAX=60`）+ `ConfirmAction` 枚举（destructive 二次确认）。

> 直接结论：**后端逻辑几乎可 1:1 迁移到 egui 版**，只需把 UI 从 ratatui 换成 egui。

### 2.3 lazywslcontainer（Go，交互与统计设计参考）

- 栈：bubbletea（MVU：Model/Update/View）+ lipgloss（样式）。
- 后端 `internal/client`：`run()` 用 `exec.CommandContext`，`runJSON()` 统一 JSON 解析并优雅降级到文本（`errTextOnly`）。
- **stats.go 的 sparkline 值得学**：`sparklineMulti(vals,width,height,min,max)` 用 `▁▂▃▄▅▆▇█` 8 级块渲染 3 行图；CPU 固定 0–100% 青色、Mem 动态 min/max 品红色；60 样本、2s tick。
- 交互：`/` 过滤、鼠标点击选择/切 tab、destructive `y/n` 确认、run/build 内联参数提示（`--name N -d --rm -p H:C IMAGE`）。
- inspect.go：递归 pretty-print JSON（key 排序、缩进）。

> 借鉴点：**实时 sparkline 的采样/归一化算法**、**内联 run 参数解析**、**确认框交互**，移植到 egui 的绘图 API（egui 可用 `Plot` 或自绘线，比 ASCII 更精细）。

### 2.4 Docker Desktop（GUI 形态与体验标杆）

- **架构**：宿主侧 = Electron+React GUI + docker CLI（原生）+ 端口/文件映射适配层 + VM 生命周期管理；VM 侧 = `dockerd → containerd → runc`，**所有容器共享一个 Linux VM**（Windows 上 WSL2 backend）。
- **功能矩阵**：容器/镜像/卷/网络 dashboard、日志、exec、资源滑块、Compose、一键 K8s、扩展市场、Scout 漏洞扫描、Model Runner（本地 LLM）。
- **短板**：重（GUI ~200-400MB + VM ~1-2GB 基线）、大团队商业授权、闭源。

**与 wslc 的本质差异**：wslc **每个 CLI/API 会话起独立 Hyper-V VM**（强隔离、企业友好），Docker Desktop 是单共享 VM（更省资源）。wslc 缺 Compose、缺 GUI、缺扩展生态。

> 借鉴点：**布局与信息架构**（左侧资源导航 + 右侧详情多 tab）、**destructive 操作的确认与 toast 反馈**、**空状态引导**。但坚决不学它的「重」——本项目要单文件、秒开、低占用。

**源码归属（2026-07-15 拉取拆解）**：

- `lazywslc` — **Craig Loewen (Microsoft, WSL 团队)**，Rust + ratatui 0.29 + crossterm + tokio；后端范式直接可迁移（见 §2.2）。
- `lazywslcontainer` — **Gregor Pilar**，Go + bubbletea + lipgloss；交互与 ASCII sparkline 设计参考（见 §2.3）。
- 二者**均不含网络管理**，且为终端 TUI；`wslc-desktop` 以窗口化 GUI + 网络管理形成差异化。

**战略合成**：吸收两 TUI 的「实时统计 + 流式日志 + 行内操作」交互精髓，并补齐其共同的网络管理缺口；对 Docker Desktop 的「重」与 wslc 单 VM/强隔离本质冲突的高阶能力（CVE/SBOM/拖拽）**明确不做**，坚守单文件轻量优势。可吸收的 M2 增量：日志正则搜索/高亮、列排序、命令模板、镜像 build、MSI 打包。

## 3. wslc CLI 能力矩阵（本机 wslc 2.9.3.0 实测）

所有 schema 均在用户本机 **实测确认**（gold standard，非文档推测）。

### 3.1 只读 / 列表（均支持 `--format json`）

| 命令 | 输出 schema（PascalCase） | 备注 |
|---|---|---|
| `wslc list --all --format json` | `[{CreatedAt, Id, Image, Name, Ports[], State, StateChangedAt}]` | **无版权头**；`Ports[]`={BindingAddress, ContainerPort, HostPort, Protocol} |
| `wslc stats --format json` | `[{ID, Name, CPUPerc:"0.25%", MemUsage:"63.16 MiB / 15.48 GiB", MemPerc, NetIO, BlockIO, PIDs}]` | 字符串型百分比/用量，需解析 |
| `wslc images --format json` | `[{Created, Id:"sha256:..", Repository, Size(bytes), Tag}]` | Size 为字节整数 |
| `wslc volume list --format json` | `[{Driver:"guest", Name}]` | |
| `wslc inspect <id>` | 原始 JSON | 详情/inspect tab |
| `wslc logs <id> [-n N] [-t] [-f]` | 文本 | 日志 tab |

**State 实测映射**（本机 8 running / 3 exited）：`2 = Running`、`3 = Exited`。结合 lazywslc/lazywslcontainer 源码，完整枚举取：`1=Created, 2=Running, 3=Exited, 4=Paused`（保守：未知值归 Unknown）。
**Protocol 映射**：`6 = tcp`、`17 = udp`（IP 协议号）。

### 3.2 写操作 / 生命周期

| 类别 | 命令 |
|---|---|
| 容器 | `start` / `stop` / `restart` / `kill` / `rm [--force]` / `run` / `exec` / `container prune` |
| 镜像 | `pull` / `rmi` / `image prune` / `build -t <tag> <path>` / `run <image>` |
| 卷 | `volume remove` / `volume prune` |
| 注册表 | `registry login` / `registry logout` |

**已知不支持的 flag**（来自 wslc-menu.ps1 踩坑）：`--restart`、`--privileged`、`--hostname`（用 `-h`）。

### 3.3 真实用户场景（来自 wslc-menu.ps1）

用户本机实际跑 **27 个 PT/辅种/homelab 容器**（qinglong、jackett、peerbanhelper、quark-auto-save、home-assistant 等），镜像大量走国内镜像源（`docker.1panel.live`、`registry.cn-*.aliyuncs.com`、`ghcr.io/schalkiii/*`）。→ GUI 需良好处理**长镜像名、端口列表、中文/localized 输出**，并可考虑内置**镜像源回退**（后续）。

## 4. 架构与技术选型

### 4.1 GUI 框架决策：egui/eframe（最终）

| 评估项 | egui/eframe ✅ 选定 | Tauri（备选） |
|---|---|---|
| 交付物 | **单一 .exe，零运行时依赖** | 需 WebView2 运行时 + web 前端资源 |
| 工具链 | 仅 cargo | cargo + Node/npm + 前端框架 |
| 实时数据/表格/sparkline | 即时模式，天然适合每帧刷新 | 需前后端 IPC 桥接 |
| 视觉上限 | 中（功能型 UI 足够） | 高（consumer 级美观） |
| 迭代速度 | 快（改 Rust 即见） | 中（前后端两套） |
| 契合用户偏好 | **自包含、无外部依赖、优雅** | 依赖较重 |

**决策**：MVP 采用 **egui/eframe**。理由——即时模式最契合本工具的核心（实时统计表 + CPU/内存曲线），单文件零依赖符合用户一贯偏好，纯 cargo 构建迭代最快。本机未检出 WebView2、crates.io sparse index 经代理可达，进一步支持该选择。Tauri 记为**后续可选**（若要做 consumer 级视觉）。

### 4.2 分层架构

```
┌─────────────────────────────────────────────┐
│  UI 层 (egui)                                 │
│  ├─ 左侧导航: Containers / Images / Volumes    │
│  ├─ 主区表格 + 选中详情多 tab                   │
│  │    (Logs · Stats · Inspect)                │
│  ├─ 顶部工具栏: 刷新 / 过滤 / Run 对话框         │
│  └─ 确认框 + Toast 反馈                         │
├─────────────────────────────────────────────┤
│  App 状态层 (src/app.rs)                       │
│  ├─ 数据缓存: containers/images/volumes        │
│  ├─ StatsHistory: HashMap<Id,{cpu,mem VecDeque}>│
│  ├─ 选中/过滤/tab/确认 状态                     │
│  └─ 后台轮询线程 ↔ UI: mpsc channel            │
├─────────────────────────────────────────────┤
│  wslc 客户端层 (src/wslc/) — 框架无关           │
│  ├─ client.rs: 进程派生 + CREATE_NO_WINDOW      │
│  │             + 超时 + 头部清洗                │
│  ├─ commands.rs: list/images/stats/... 封装     │
│  └─ types.rs: serde PascalCase 结构 + 辅助      │
├─────────────────────────────────────────────┤
│  wslc.exe (Microsoft)                         │
└─────────────────────────────────────────────┘
```

**关键设计**：
1. **后端框架无关**：`src/wslc/` 不依赖 egui，纯 `std::process` + serde，可单测、可复用（未来换 Tauri 也不动）。
2. **UI 线程不阻塞**：所有 `wslc` 调用在后台线程，结果经 `std::sync::mpsc` 回传；每次调用带 `CREATE_NO_WINDOW`（不弹黑窗）+ 超时。
3. **轮询节奏**：列表 2s、stats 2s（对齐竞品）；日志按需拉取。
4. **destructive 二次确认**：rm / prune / kill 走 `ConfirmAction` 弹窗。
5. **统计历史**：每容器 CPU/Mem 各存 60 样本 `VecDeque`，用 egui `Plot` 画曲线（比 ASCII sparkline 更精细）。

### 4.3 技术栈

| 组件 | 选型 | 版本 |
|---|---|---|
| GUI | eframe / egui | 0.29+ |
| 序列化 | serde / serde_json | 1 |
| 错误 | anyhow | 1 |
| 时间 | chrono | 0.4 |
| 进程 | std::process（同步，后台线程） | std |
| 目标 | x86_64-pc-windows-msvc | — |

> 不引入 tokio：GUI 场景用「后台 std 线程 + channel」更简单，避免异步运行时复杂度（lazywslc 用 tokio 是因 ratatui 事件循环，egui 自带帧循环，无此必要）。

## 6. 风险与应对

| 风险 | 应对 |
|---|---|
| wslc 预览版命令/schema 变动 | 后端 serde 用 `#[serde(default)]` 容错；schema 集中在 types.rs 便于跟版 |
| 某些命令无 JSON（如 logs/inspect 文本） | 分离「JSON 命令」与「文本命令」路径，文本直接展示 |
| 每次调用弹黑窗 | Windows `CREATE_NO_WINDOW` 标志（已验证 lazywslc 方案） |
| wslc 调用慢/卡死 | 后台线程 + 超时 kill，UI 显示 loading/错误 toast |
| 大量容器/长镜像名 | 表格列可省略号截断 + hover 全文；虚拟滚动（后续） |

## 7. 结论

- 竞品全是 TUI 或不接 wslc 的重型 GUI → **wslc 的轻量 GUI 空白确认**。
- `lazywslc` 提供了**经过验证的 Rust wslc 后端范式**，可直接迁移。
- 选 **egui/eframe**：单文件、零依赖、实时数据友好、契合用户偏好。
- 本机 wslc 2.9.3.0 schema 已实测锁定，types.rs 可精确建模。
- 下一步：按 §4.4 结构实现 M1，编译并对本机真实容器冒烟测试。
